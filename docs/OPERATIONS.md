# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 修复来源文件，重新上传并执行。历史批次保留供复核。
4. 对账无差异且无坏行时可签发。对仍有差异的版本可填写暂缓意见。
5. 导出复核证据并保存于交接记录。

## 迟到来源补录

1. 在批次复核区选择补录 CSV 并提交，系统把补录挂到当前批次的来源版本链上。
2. 无依据或矛盾补录会被拒绝：通知栏给出原因码，补录尝试区列出全部参与记录与源行号，已签发结论和证据保持原样。
3. 通过校验的补录生成新版本批次，仅受影响业务分组按新口径重算，其余分组显示"沿用已签发结论"。
4. 在来源版本链中点击任意历史版本可单独回读；旧版报告、复核状态与证据下载均不可变。
5. 新版本对账无差异且无坏行时方可签发；仍有差异时只能暂缓并填写意见。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。
